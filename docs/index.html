春晚舞蹈机器人

把一段春晚群舞视频，变成 9 台 Unitree G1 人形机器人同步起舞。复刻 Datawhale every-embodied 教程，全链路跑通：视频 → 人体姿态 → 动作重定向 → 机器人 3D 演示。

9 位舞者 → 9 台机器人 PromptHMR · SMPL-X GMR 重定向 Unitree G1 · 29 DoF Kaggle GPU 推理 + Mac 本地演示

演示

左：输入的人类群舞原片（前 24s）。右：重定向后 9 台 Unitree G1 的 3D 动作（viser 逐帧渲染，含原视频相机锥）。两侧均为 720 帧 @30fps，逐帧对齐。

输入 人类群舞原片
dance_1.mp4 · 1280×720 · 检出 9 位舞者
输出 9 台 Unitree G1 机器人
viser 3D 场景 · 720 帧 @30fps · SMPL-X → GMR → G1 29 DoF

人体动作 ──重定向──▶ 机器人关节轨迹

机器人侧由 viser 3D 演示逐帧定格截取后合成（非实时录屏，静态页无法承载 3D 引擎）， 因此播放完全流畅，且与左侧原片逐帧对齐。完整交互版（可旋转视角、逐帧、切换轨迹）见下方「本地运行」。

技术管线

五阶段，重推理在 Kaggle GPU（P100，全流程约 90–100 分钟），3D 演示在 Mac CPU。

01
输入视频
春晚群舞 dance_1.mp4，1180 帧 / 30fps，detectron2 检出 9 位舞者
02
PromptHMR
单目视频 → SMPL-X 人体网格与姿态序列（--static-camera 绕开缺失的 SLAM 权重）
03
GMR 重定向
SMPL-X 人体动作 → Unitree G1 的 29 DoF 关节轨迹（root_pos / root_rot / dof_pos）
04
机器人动作
9 条 robot_motion_track，逐帧 38 连杆位姿，30fps
05
viser 3D 演示
Mac 本地 CPU 实时渲染，浏览器交互（旋转 / 逐帧 / 多轨迹）

踩过的坑（复现关键）

  • 环境必须用 PromptHMR 的 PT2.4 分支（py3.11 + torch2.4.0cu121 + 4 个 cp311 wheel），官方 phmr.yml 必失败
  • 必须 checkout 基线 commit（PromptHMR 4f8915c / GMR 069b4fd）再打 3 个 patch
  • 推理加 --static-camera 绕开权重仓缺失的 droid.pth
  • cam_calib.py 硬编码作者路径 → ln -s <PromptHMR根> /code
  • Kaggle /kaggle/working 仅 20G → 权重与环境放 overlay 大盘

诚实边界：本项目是 Datawhale every-embodied 教程的复刻，核心算法（PromptHMR / GMR）来自上游； 本人的工作是把三仓 vendor 进一个可复现仓库、适配 Kaggle kernel、打 patch 修通环境、并做出 Mac 本地交互演示。详见仓库 PATCHES.md 与 Acknowledgement。

本地运行（交互式 3D）

# 1) Kaggle GPU 推理产出动作文件（见仓库 kaggle/main.py，18 步全流程）
#    产物：results.pkl + robot_motion_track_*.pkl + original.mp4

# 2) Mac 本地起 viser 交互演示（CPU 即可，无需 GPU）
conda create -n v2rviz python=3.11 -c conda-forge --override-channels
conda activate v2rviz && pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install viser==0.2.23 trimesh opencv-python joblib scipy

# 3) 把 Kaggle 产物放进 video2robot/data/video_001/，然后：
./run_demo.sh                 # 全部 9 条轨迹
./run_demo.sh --tracks 1      # 只看第 1 台
# 浏览器打开 http://localhost:8789
